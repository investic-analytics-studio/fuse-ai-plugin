# ขั้น 0 — ทางเข้า

หน้านี้ไม่ได้ทำงานอะไรเอง มันตอบคำถามเดียวคือ **"ตอนนี้อยู่ขั้นไหน และขั้นถัดไปต้องได้อะไรก่อน"**
อ่านหน้านี้ก่อนตอบคนที่เพิ่งลงแพ็กเกจเสร็จ เพราะสิ่งที่เขาเห็นคือ tool แปดตัวกับสกิลเก้าใบ ซึ่งไม่ได้บอกว่าต้องเริ่มตรงไหน

**ห้ามเดินเลยขั้นที่ 9 จากข้อความแรกของผู้ใช้** ถึงเขาจะเขียนมาละเอียดแค่ไหน ขั้น 9 คือขั้นที่หักเงิน

## คนที่เพิ่งมาถึง ถามสามข้อนี้ก่อน ไม่ใช่สิบข้อ

สามข้อนี้ล็อกของที่เปลี่ยนกลางทางไม่ได้ จึงต้องรู้ก่อน ที่เหลือ (คอนเซปต์ Hook จำนวนซีน ตัวละคร) ไปถามในขั้น 6

1. **คลิปนี้เอาไปลงที่ไหน และยาวประมาณเท่าไร** → ล็อก aspect กับความยาวรวม หนึ่งโปรเจกต์ผูกกับ aspect เดียวตั้งแต่สร้าง เปลี่ยนทีหลังคือขึ้นโปรเจกต์ใหม่
2. **มีรูปหรือคลิปของจริงอยู่ในมือไหม** → ล็อกว่างานไปทาง `t2v` (prompt ล้วน) หรือ `i2v` (ต้องมีภาพอ้างอิง) ถ้าไม่มีรูป ต้องบอกเขาตอนนี้ว่าหน้าตาสินค้าและตัวละครจะไม่ตรงกันข้ามซีน ไม่ใช่ให้เขาไปเจอเองตอนขั้น 9
3. **ต้องมีเสียงพูดไหม** → ถ้าต้องมี งานนี้มีงบสองก้อนคนละบัญชี: token ของ Fuse สำหรับภาพ และบัญชี ElevenLabs ของเขาเองสำหรับเสียง ห้ามรวมสองยอดเป็นตัวเลขเดียว

ถ้าเขาตอบไม่ได้ทั้งสามข้อ ยังเดินต่อได้ถึงขั้น 4 (วิเคราะห์) โดยไม่ต้องรู้คำตอบ แต่บอกเขาว่าค้างอะไรไว้

## งานทั้งงานมีสิบขั้น

ช่อง "ต้องได้อะไรก่อนเดินต่อ" คือเงื่อนไขจริง ไม่ใช่คำแนะนำ ขั้นที่ยังไม่ได้ของในช่องนั้น ห้ามข้ามไปขั้นถัดไป

| ขั้น | ทำอะไร | ต้องได้อะไรก่อนเดินต่อ | อ่านอะไร |
|---|---|---|---|
| 1 | เคาะโจทย์จากสามข้อข้างบน | ประโยคเดียวที่บอกว่าคลิปนี้ขายอะไร ให้ใครดู ลงที่ไหน ยาวเท่าไร | หน้านี้ |
| 2 | เลือกแนวงาน | ชื่อแนว และอ่านสกิลแนวนั้นแล้ว (ซ้อนกันได้ อ่านหลายใบได้) | `genre-food` `genre-product` `genre-series` `genre-vox` |
| 3 | เปิด Asset ของจริงที่เขาให้มา | รายการไฟล์จริงพร้อมบอกว่าอะไรยังขาด ไม่ใช่สรุปจากชื่อไฟล์ | `01-analysis` |
| 4 | วิเคราะห์ | analysis brief ที่ผู้ใช้อ่านแล้ว **หยุดให้เขาอ่านก่อน** ไม่ไหลไปวางแผนในทีเดียว | `01-analysis` |
| 5 | อ่านของที่มีขายวันนี้ด้วย `fuse_tiers` | tier ที่รองรับของที่งานต้องใช้จริง (โหมด ความละเอียด aspect ภาพจบ ช่วงวินาที) ถ้าไม่มี tier ไหนรองรับ ให้บอกเขาว่ามีอะไรให้เลือกจริง ไม่เปลี่ยนแผนเงียบ ๆ | `03-generation` |
| 6 | แผน สคริปต์ตามเวลา สตอรี่บอร์ด | บอร์ดที่ผู้ใช้อนุมัติ + slug รายซีน + วินาทีรายซีน + prompt ที่เขาอ่านแล้ว (แก้ prompt หลังจ่ายแล้วคือจ่ายใหม่) | `02-planning` |
| 7 | ล็อกภาพอ้างอิง | URL จาก `fuse_upload` ของภาพที่ผู้ใช้อนุมัติแล้ว — ไฟล์ในเครื่องส่งเข้าขั้น 9 ตรง ๆ ไม่ได้ และ URL ที่ได้เป็นลิงก์สาธารณะ ต้องถามก่อนอัป | `03-generation` |
| 8 | เลือกเสียง ถ้างานมีเสียงพูด | voice id กับโมเดลที่พูดภาษาของบทได้ และผู้ใช้ฟังของจริงแล้ว — บทไทยต้องเลือกโมเดลที่รองรับ `th` เอง โมเดลตั้งต้นพูดไทยไม่ได้ | `02-planning` → `fuse_voices` |
| 9 | ตีราคา → ขออนุมัติ → สร้างคลิป → ตรวจ | **ประตูเงิน:** ยอดจาก `fuse_quote` ที่ผู้ใช้เห็น และเพดาน token เป็นตัวเลขจากปากเขา จากนั้น `fuse_scenes` และทุกซีนต้องถึงสถานะ "ตรวจแล้ว" ไม่ใช่ "สร้างสำเร็จ" | `03-generation` + `shot-checks` |
| 10 | วัดด้วย `fuse_manifest` → ตัดต่อ → เรนเดอร์ | ไฟล์คลิปจริงบนเครื่องเขา และเขาได้ดูของที่เรนเดอร์แล้ว — ขั้นนี้ไม่เสีย token ฉะนั้นแก้อะไรได้ในขั้นนี้ให้แก้ที่นี่ | `04-editing` + `shot-checks` |

สองอย่างที่ต้องพูดกับผู้ใช้ตั้งแต่ขั้น 1 ไม่ใช่ตอนขั้น 9:

- **ขั้น 9 เป็นขั้นเดียวที่หักเงิน** ขั้น 1–8 ตีราคาและวางแผนได้ฟรี ขั้น 10 รันบนเครื่องเขาและไม่เสียอะไร
- **การถามว่า "เริ่มเลยไหม" ไม่ใช่การอนุมัติให้จ่ายเงิน** การอนุมัติคือตัวเลขเพดาน token ที่เขาพูดออกมา

## เวลาที่ใช้จริง

ตัวเลขข้างล่างวัดจากงานจริงหนึ่งงาน (3 ซีน `t2v` tier ล่าง 480p 5 วินาที บน Windows, Node 24, ffmpeg 8.1) ไม่ใช่คำสัญญา — ของจริงขึ้นกับคิวของ provider ในนาทีนั้น:

- **ขั้น 9 สร้างคลิป:** 3 ซีนยิงขนานกัน เสร็จทั้งหมดใน 109–126 วินาที ไม่ใช่หลักสิบนาที
- **ขั้น 10 เรนเดอร์:** คลิปยาว 15.5 วินาทีที่ 864×480 ใช้ 37 วินาที ส่วนงานที่ 1944×1080 ยาว 12 วินาที ใช้ 2 นาที 30 → **ความละเอียดเป็นตัวกำหนดเวลาเรนเดอร์ ไม่ใช่ความยาวคลิป**
- เวลาที่กินจริงของงานทั้งงานอยู่ที่ขั้น 4 กับขั้น 6 เพราะเป็นขั้นที่คนต้องตัดสินใจ ไม่ใช่ขั้นที่รอเครื่อง อย่าบอกผู้ใช้ว่า "อีกสิบนาทีเสร็จ" โดยนับแต่เวลาเครื่อง

## ตารางสถานะ: ตอนนี้อยู่ขั้นไหน

แสดงตารางนี้ทุกครั้งที่เริ่มงานใหม่ ทุกครั้งที่กลับมาทำต่อ และทุกครั้งที่ผู้ใช้ถามว่าถึงไหนแล้ว
ช่องที่ยังไม่มีคำตอบให้เขียนว่า **ยังไม่เลือก** ตรง ๆ **ห้ามปล่อยขีดว่าง ห้ามเติมค่าจากงานก่อนหน้า และห้ามเดา**

| เรื่อง | สถานะ |
|---|---|
| แนวงาน | |
| aspect กับความยาวรวม | |
| tier กับความละเอียด | |
| โหมด (`t2v` / `i2v`) | |
| ภาพอ้างอิงที่อนุมัติและอัปแล้ว | |
| บอร์ดที่ผู้ใช้อนุมัติ | |
| เสียงพูด (voice id + โมเดล) | |
| เพดาน token ที่ผู้ใช้อนุมัติ | |
| ซีนที่จ่ายแล้ว / ตรวจแล้ว / อนุมัติแล้ว | |
| ไฟล์ที่เรนเดอร์แล้ว | |

สามช่องสุดท้ายแยกกันเสมอ: **จ่ายแล้ว** คือหักเงินไปแล้ว **ตรวจแล้ว** คือมีคนเปิดดูของจริงแล้ว **อนุมัติแล้ว** คือผู้ใช้บอกว่าผ่าน ไม่ยุบสามคำนี้เป็นคำเดียว

## เข้ากลางทางได้ ถ้ามีของอยู่แล้ว

อย่าลากคนที่มีของมาแล้วกลับไปเริ่มที่ขั้น 1 ดูของที่มีจริงก่อนแล้วเข้าขั้นที่ตรงกัน:

| ผู้ใช้มีอะไรอยู่ | เข้าที่ขั้น |
|---|---|
| โฟลเดอร์โปรเจกต์ที่มี `.fuse/job.json` | ขั้น 9 — เรียก `fuse_scenes` **ด้วยอาร์กิวเมนต์ชุดเดิม** เพื่อทำต่อ อย่าสร้างโปรเจกต์ใหม่และอย่าเปลี่ยน slug ไม่งั้นซีนที่จ่ายไปแล้วจะไม่ถูกนับและจ่ายซ้ำ |
| คลิปรายซีนครบและตรวจแล้ว | ขั้น 10 |
| บอร์ดที่อนุมัติแล้ว | ขั้น 5 (เช็ก tier ก่อน แล้วไป 9) |
| มีแต่รูปสินค้าหรือคลิปอ้างอิง | ขั้น 3 |
| ไม่มีอะไรเลย | ขั้น 1 |

## สี่ข้อที่ต้องตอบตรงนี้ ไม่ใช่ให้ลูกค้าไปเจอเองตอนขั้น 9

- **ไม่มี tool ดูยอดคงเหลือ** คีย์ API อ่านยอดไม่ได้ จะรู้ว่าเงินไม่พอตอนถูกปฏิเสธเท่านั้น ฉะนั้นต้องถามผู้ใช้ว่ายอดพอไหมก่อนเริ่ม และ **ไม่ "ลองยิงหนึ่งซีนดู" เพื่อเช็กยอด** เพราะนั่นคือจ่ายเงินจริง
- **แพ็กเกจนี้ไม่สร้างดนตรี Ambience หรือ SFX** มีแต่เสียงพากย์ สามอย่างนั้นมาจากฝั่งผู้ใช้แล้วไปมิกซ์ในขั้น 10
- **ปากไม่ลิปซิงก์กับบทพากย์** เสียงมาจากคนละที่กับภาพ ให้วางบทไว้กับช็อตที่ไม่เห็นปากชัด หรือยอมรับว่าปากไม่ตรง
- **ภาพอ้างอิงใบเดียวไม่รับประกันทุกเฟรม** มันคุมได้แค่จุดเริ่มของซีน กลางซีนยังเพี้ยนได้ ถ้างานต้องตรงระดับพิกเซล ทางแก้คือคอมโพสิตในขั้น 10 ไม่ใช่ยิงซ้ำเรื่อย ๆ
