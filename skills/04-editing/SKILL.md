# ขั้น 4 — ตัดต่อและเรนเดอร์ (ทำงานบนเครื่องผู้ใช้ ไม่เสีย token)

ขั้นนี้ไม่เรียก tool ของ Fuse อีก ทุกอย่างรันในเครื่อง การแก้ที่ทำได้ในขั้นนี้ **ควรทำในขั้นนี้** เพราะการกลับไปเจนซีนใหม่คือการจ่ายเงินใหม่ (และต้องให้ผู้ใช้อนุมัติราคาก่อน)

## เริ่มจากสิ่งที่วัดมาแล้ว

1. อ่าน `assets/scenes/manifest.json` (จาก `fuse_manifest`) มันมีสี่อย่างที่เขียน composition ให้ถูกไม่ได้ถ้าไม่มี: **canvas** ไปใส่ `data-width`/`data-height`, กล่อง CSS และ viewport · **ความยาวจริงต่อซีน** ไปวางไทม์ไลน์ (ไม่ใช่ความยาวที่ขอไว้ในแผน) · **`fps`** ไปใส่ `data-fps` บน root · **`hasAudio`** เป็นตัวตัดสินว่าคลิปมีเสียงติดมาหรือไม่
2. **ห้ามเดา canvas และห้ามอัปสเกล** canvas ที่ใหญ่กว่าคลิปจะยืดฟุตเทจและทำเวลาเรนเดอร์บานโดยไม่ได้คุณภาพกลับมา ถ้าสองซีนพิกเซลไม่เท่ากัน manifest ใช้กล่องใหญ่สุดเพื่อไม่ให้ซีนไหนถูกขยาย ให้จัดวางซีนที่เล็กกว่าในกล่องนั้นโดยรักษาสัดส่วน
3. **ตั้ง `data-fps` ตาม `fps` ใน manifest เสมอ** HyperFrames เรนเดอร์ที่ 30 fps ถ้าไม่สั่ง ฟุตเทจ 24 fps ที่ปล่อยไว้จึงถูกส่งมอบโดยมีเฟรมซ้ำทุกเฟรมที่ห้า (วัดจากงานจริง: 466 เฟรม ซ้ำ 125) ไฟล์ใหญ่ขึ้นโดยไม่ได้ภาพดีขึ้น · ถ้า manifest ไม่มี `fps` แปลว่าวัดไม่ได้ ให้บอกผู้ใช้ตามนั้น ไม่เดาเลขเอง
4. อ่าน `CLAUDE.md`/`AGENTS.md` และสกิลที่ `hyperframes init` วางไว้ในโปรเจกต์ **ความรู้เรื่องการเขียน composition เป็นของ HyperFrames** สกิลนี้ไม่สอนแทน และแพ็กเกจของ Fuse ไม่เขียน composition ให้

คำสั่งที่ใช้รันผ่าน shell ของไคลเอนต์ (เวอร์ชันถูก pin ไว้ใน `package.json` ของโปรเจกต์แล้ว):

```bash
npx hyperframes lint      # จับปัญหาก่อนเรนเดอร์ รวมฟอนต์ไทยที่กลายเป็นกล่องเปล่า
npx hyperframes check     # ตรวจ composition
npx hyperframes render    # เรนเดอร์จริง
```

ฟอนต์ไทยอยู่ในโปรเจกต์แล้วเป็นไฟล์ `.woff2` พร้อม `assets/fonts/noto-sans-thai.css` ให้ `@import` ไฟล์นั้น **ห้ามชี้ไป Google Fonts ตรง ๆ** เพราะ Chrome ที่เรนเดอร์ไม่มีฟอนต์ไทยในเครื่องและจะได้กล่องเปล่า ถ้า `lint` ฟ้องเรื่องฟอนต์แปลว่าตอนสร้างโปรเจกต์โหลดฟอนต์ไม่สำเร็จ ให้วางไฟล์ woff2 เองก่อนเรนเดอร์

## ขั้นแรก: รวมคลิปที่ผ่านแล้วเป็นฉบับภาพ

- เลือก **เวอร์ชันล่าสุดที่ผ่านการตรวจหรือที่ผู้ใช้สั่งให้ใช้** ต่อ Shot ID ห้ามดึงเวอร์ชันที่ถูกสั่งแก้หรือถูกแทนที่กลับมาเพราะชื่อไฟล์ดูใหม่กว่า บันทึกที่มาของการเลือกตรงไปตรงมา
- ทำรายการไฟล์ต้นทาง Shot ID เวอร์ชัน และช่วงเวลาบนไทม์ไลน์ ตรวจว่าไฟล์ครบก่อนเรนเดอร์ ถ้าสถานะคลุมเครือจนเลือกผิดได้ ให้จัดเตรียมส่วนที่ชัดเจนแล้วถามเฉพาะส่วนที่ขาด
- ต่อคลิปตามสคริปต์และบอร์ด รักษาลำดับ การกระทำ ทิศกล้อง จังหวะ และรอยต่อที่ผ่านแล้ว **ไม่กลับภาพ ไม่ย้อนคลิป ไม่เร่งหรือชะลอ ไม่เปลี่ยนคนหรือสินค้าเพื่อกลบรอยต่อ**
- **ดู `hasAudio` ใน manifest ก่อนจะใส่ `muted`** บาง tier คืนคลิปที่มีเสียงบรรยากาศติดมาด้วย (ยืนยันจากงานจริง: คลิป t2v-low-standard มีแทร็ก AAC ดังจริงทั้งสามซีน) เสียงนั้นผู้ใช้จ่ายไปแล้วพร้อมกับภาพ **การใส่ `muted` ทับคือการทิ้งของที่ซื้อมาแบบเงียบ ๆ** ถ้า `hasAudio` เป็น true ให้เก็บเสียงไว้บน `<video>` ด้วย `data-has-audio="true"` และไม่ใส่ `muted` เว้นแต่ผู้ใช้สั่งให้เงียบหรือจะแทนด้วยแทร็กของเขาเอง — ซึ่งต้องเป็นการตัดสินใจที่พูดออกมา ไม่ใช่ค่าเริ่มต้นที่เกิดจากการไม่ได้ดู
- ถ้า `hasAudio` เป็น false (คลิปต้นทางเงียบจริง) ให้เรียกผลลัพธ์นี้ว่า **ฉบับภาพ เสียงยังไม่มิกซ์** ไม่อ้างว่า SFX หรือดนตรีเสร็จแล้ว · คำเตือน `film_silent` ของ `hyperframes check` ในกรณีนั้นคือคำเตือนที่ตั้งใจให้เหลือไว้ แต่ **ถ้า `hasAudio` เป็น true แล้วยังเจอ `film_silent` แปลว่าเรา mute เสียงที่ซื้อมา ไม่ใช่คำเตือนที่ข้ามได้**

## เสียงที่ตรงกับการกระทำ

พากย์อยู่ใน `assets/audio/` แล้วถ้าขั้น 3 สร้างไว้ (ชื่อไฟล์คือ `<slug>-<hash>.mp3` และ hash คือใบเสร็จของบรรทัดนั้น **ห้ามเปลี่ยนชื่อหรือลบ** เพราะจะทำให้รอบถัดไปจ่ายเงินใหม่) ดนตรี Ambience และ SFX มาจากฝั่งผู้ใช้ แพ็กเกจนี้ไม่สร้างสามอย่างนั้น งานของขั้นนี้คือวางให้ตรงกับภาพ

ถ้าบทต้องแก้ตอนนี้ **ห้ามเร่งหรือยืดเสียงเพื่อให้พอดี** และ**ห้ามสร้างเสียงใหม่ในขั้นนี้** — การพากย์ใช้เงินของผู้ใช้ จึงอยู่ในขั้น 3 ที่เดียวเหมือนการสร้างคลิป ให้กลับไปขั้น 3 พร้อมบรรทัดที่ต้องแก้ แล้วบอกผู้ใช้ว่าเป็นค่าใช้จ่ายเพิ่มบนบัญชี ElevenLabs ของเขา บรรทัดอื่นที่ไม่แก้ไม่เสียเงินซ้ำ

1. ดูภาพที่เรนเดอร์แล้วรายซีนและจดเวลาเหตุการณ์จริง (มือเคลื่อน ของสัมผัสน้ำ การคน การกิน การมองกล้อง) ไม่อิงเวลาเริ่มซีน
2. วางคำที่กล่าวถึงการกระทำให้ตรงกับการกระทำนั้น
3. ใช้การเลื่อนเสียงและจัดช่วงเงียบก่อน **ไม่เร่งหรือชะลอเสียงพูดหรือภาพเพื่อฝืนให้พอดี** ไม่ตัดพยางค์หรือท้ายคำ
4. ตรวจรูปคลื่นประกอบจุดตัด เวลาอักขระที่บริการใด ๆ คืนมาอาจคลาด ห้ามถือว่าแม่นทุกคำโดยไม่ตรวจ ถ้าตรวจไม่ได้ให้บอกขอบเขตการตรวจตามจริง · ความยาวพากย์ที่ขั้น 3 ส่งมาวัดด้วย ffprobe จึงเป็นความยาวไฟล์จริง แต่ไม่ได้บอกว่าคำไหนอยู่ตรงไหน
5. ถ้าประโยคยาวเกินพื้นที่จริงจนแก้ด้วยช่องไฟไม่ได้ ให้เสนอปรับบทหรืออัดใหม่ ไม่เร่งเสียงเงียบ ๆ
6. ใช้ผู้พากย์คนเดิมตลอดคลิป ถ้าแก้เฉพาะ CTA ให้แก้เฉพาะส่วนนั้นด้วยเสียงเดิมแล้วตรวจความต่อเนื่อง ไม่ทำแทร็กใหม่ทั้งเส้นโดยไม่จำเป็น
7. ถ้าคลิปจากโมเดลมีเสียงพูดติดมา ให้ตัดเฉพาะเสียงพูดนั้นออกเมื่อใช้แทร็ก VO ของตัวเอง

**ASMR, SFX, Ambience, BGM:** เสียงต้องสนับสนุนการกระทำที่เห็นและ Mood & Tone ไม่เพิ่มความดังหรือจำนวนเอฟเฟกต์เพื่อให้คลิปดูมีงานมากขึ้น เสียงต้องพอดีกับขนาดของการกระทำ (น้ำกระเซ็นเล็กไม่ใช้เสียงสาดใหญ่) ไม่ใส่เสียงเคี้ยวหรือซู้ดเมื่อภาพไม่ได้กิน ใช้ fade สั้นกันรอยตัด รักษาช่วงเงียบไว้ ไม่ normalize จนช่วงเงียบมีเสียงรบกวน · สถานะ "เรนเดอร์ได้" ไม่ใช่หลักฐานว่าเสียงฟังดี

## แก้ภาพเฉพาะจุด

- ตีกรอบก่อนลงมือว่า **แก้อะไร** และ **อะไรต้องเหมือนเดิม** (รูปทรง คน สินค้า ฉาก การเคลื่อนไหว)
- ใช้การปรับสี แสง mask tracking หรือ compositing ที่ควบคุมผลได้ **ไม่เจนซีนใหม่ทั้งซีน** เพราะส่วนที่ผ่านแล้วจะเปลี่ยนไปด้วยและเสียเงินอีกรอบ
- พูดถึงผลตามที่ทำได้จริง การปรับสีและเงาให้ดูเคลือบมันไม่ใช่การเพิ่มหยดน้ำจริง ถ้าไม่ได้เพิ่มก็ไม่อ้างว่าเพิ่ม
- ภาพแพ็กจริงที่ซ้อนลงไปต้องมีสัดส่วน perspective เงาสัมผัส และความชัดสัมพันธ์กับภาพ ไม่วางลอยและไม่ทำตัวอักษรเพี้ยน
- ตรวจ mask ตลอดช่วงการเคลื่อนไหว ไม่ดูเพียงเฟรมที่ดีที่สุด ระวังไม่ให้โดนหน้า มือ เสื้อผ้า หรือแพ็กโดยไม่ได้ตั้งใจ

## ข้อความและกราฟิก

**ค่าเริ่มต้นคือไม่ใส่ข้อความเอง** รวม Tagline, CTA, ซับ และคำบรรยาย แม้ copy จะอยู่ในแผนแล้วก็เก็บไว้จนมีคำสั่งชัดเจน ตัวอักษรและโลโก้ที่พิมพ์อยู่บนสินค้าจริงให้คงตามต้นฉบับ เมื่อผู้ใช้สั่งเพิ่ม ให้เพิ่มเฉพาะข้อความและช่วงที่อนุมัติ ไม่ขยายเป็นซับทุกซีนเอง

ก่อนทำ ให้กำหนดให้ครบ:

| รายการ | สิ่งที่ต้องกำหนด |
|---|---|
| Copy | ข้อความจริง เครื่องหมาย การแบ่งบรรทัด |
| Font | ชื่อฟอนต์ น้ำหนัก ขนาด และการรองรับภาษาไทย |
| Color | สีหรือ gradient และสีเงา/glow ที่เข้ากับ Mood & Tone |
| Placement | จุดอ้างอิง การจัดแนว และ safe zone ของสัดส่วนปลายทาง |
| Timing | เวลาเข้า ค้าง ออก และจุดที่ต้องหายหมดก่อนรอยต่อ |
| Motion | เอฟเฟกต์ ความยาว easing ความแรง |
| Protection | ไม่บังองค์ประกอบสำคัญของสินค้า คน หรือการกระทำ |

ข้อความไทยต้องตรวจสระ วรรณยุกต์ และการตัดบรรทัดจาก **ผลเรนเดอร์จริง** ไม่ใช่จากโค้ด glow ต้องช่วยอารมณ์โดยไม่ลบขอบตัวอักษร ข้อความยาวแบ่งบรรทัดได้แต่ต้องรักษาคำเดิม ส่งตัวอย่างเฉพาะซีนให้ตรวจก่อนรวมเต็มเมื่อผู้ใช้ขอ

## ตรวจและเรนเดอร์ฉบับสมบูรณ์

- รอคำสั่ง final render ตามการอนุมัติที่มีแล้ว ไม่ขออนุมัติซ้ำในสิ่งที่ผู้ใช้ยืนยันว่าไม่แก้อีก
- ตรวจว่าไฟล์ต้นทางเป็นเวอร์ชันที่ถูกต้อง รวมภาพที่แก้เฉพาะจุด เสียงที่เลือก และข้อความที่อนุมัติแล้ว
- คงความละเอียดและความเร็วตามงาน **ไม่อัปสเกลและไม่เปลี่ยนสัดส่วนเพื่อให้ดูคุณภาพสูงขึ้น**
- ถ้าไม่ได้แก้เสียง ใช้การคัดลอกแทร็กเสียงเมื่อรองรับ เพื่อรักษาเสียงและจังหวะเดิม แล้วตรวจต้นและปลายแทร็กหลัง mux
- ตรวจจากไฟล์ผลลัพธ์จริง: ความยาว จำนวนเฟรม fps รูปแบบภาพ/เสียง การเล่นจนจบ ภาพก่อน–หลังรอยต่อ ช่วงข้อความเข้าออก และตอนจบ · การตรวจตัวเลขหรือแฮชแยกจากการดูและฟังจริง บันทึกเฉพาะสิ่งที่ตรวจแล้ว
- เก็บไฟล์ชื่อมีเวอร์ชัน พร้อมรายการต้นทาง เวลาซีน ข้อมูลเสียง ข้อความ และผลตรวจ ไม่ลบเวอร์ชันที่ยังจำเป็นต่อการย้อนกลับ
- ส่งไฟล์ที่เล่นได้พร้อมความยาวและความละเอียด แยกสถานะภาพ เสียง และการรับรองของผู้ใช้ **การเรนเดอร์เสร็จไม่ใช่คำสั่งให้เผยแพร่** ไม่อัปโหลดไปช่องทางขายใด ๆ เอง
