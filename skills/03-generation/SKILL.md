# ขั้น 3 — สร้างคลิป (ขั้นเดียวที่ใช้เงิน)

ขั้นนี้รับบอร์ดที่อนุมัติแล้วมาผลิต ไม่คิดคอนเซปต์ใหม่ ไม่เปลี่ยนภาพ ไม่เปลี่ยนความยาวหรือจำนวนซีนเอง ถ้าผู้ใช้ขอแค่ตรวจความพร้อมหรือถามราคา ให้ทำเฉพาะนั้น — **การถามว่าพร้อมหรือยังไม่ใช่คำสั่งให้จ่ายเงิน**

tool ทั้งห้าตัวมาจาก MCP server ชื่อ `fuse` ถ้ายังไม่เห็น tool พวกนี้ แปลว่า server ยังไม่ได้ติดตั้งในไคลเอนต์นี้ (ดู README ของแพ็กเกจ) อย่าหาทางยิง API ของ Fuse เองด้วย curl

## ลำดับที่ต้องเดิน

```
fuse_tiers  →  fuse_quote  →  [ผู้ใช้อนุมัติงบ]  →  fuse_project_new  →  fuse_scenes  →  fuse_manifest
                                                                     เสียงพูด:  fuse_voices  →  fuse_narration (dryRun แล้วอนุมัติ)
```

### 1. `fuse_tiers` — อ่านของที่มีขายวันนี้

ไม่มีตาราง tier อยู่ในแพ็กเกจนี้และในสกิลนี้ ทุกอย่างอ่านสดจากบัญชี: ราคา base, ราคาต่อวินาทีรายความละเอียด, aspect ที่มี, และ `supportsLastImage` **ห้ามจำค่าจากงานก่อนหรือจากเอกสาร** เพราะราคาและความสามารถแก้ได้จากฝั่งเรา

เลือก tier จากสิ่งที่แผนต้องการจริง: mode (`t2v` ต้องการ prompt ล้วน / `i2v` ต้องการภาพอ้างอิง), ความละเอียด, aspect, และความต้องการภาพจบ ถ้าสิ่งที่แผนขอไม่มีใน tier ไหนเลย ให้บอกผู้ใช้ว่ามีอะไรให้เลือกจริง ไม่ใช่เปลี่ยนแผนเงียบ ๆ

### 2. `fuse_quote` — ตีราคาก่อน ไม่สร้างอะไร ไม่หักอะไร

ส่ง tier + resolution + รายการซีน (slug กับวินาที ยังไม่ต้องมี prompt) แล้ว **แสดงยอดให้ผู้ใช้เห็นเป็นรายซีนและยอดรวม** พร้อมพูดสองอย่างนี้ตรง ๆ:

- **ยอดนี้คือพื้น ไม่ใช่เพดาน** ระบบหักเงินตามคลิปที่ provider คืนมาจริง ซึ่งยาวกว่าที่ขอได้ (ขอ 5 วินาที เคยได้ 5.167 วินาที) ให้เผื่อไว้ในงบ
- **คีย์ API อ่านยอดคงเหลือไม่ได้** ไม่มี tool ดูยอด และจะรู้ว่าเงินไม่พอตอนถูกปฏิเสธเท่านั้น จึงต้องถามผู้ใช้ว่ายอดพอไหมก่อนเริ่ม ไม่ "ลองยิงหนึ่งซีนดู" เพื่อเช็กยอด เพราะนั่นคือการจ่ายเงินจริงเพื่อทดสอบ

ขออนุมัติ **เพดาน token** จากผู้ใช้เป็นตัวเลข แล้วใช้ตัวเลขนั้นเป็น `maxTokens` ตลอดงาน การอนุมัติที่ได้มาแล้วไม่ต้องขอซ้ำสำหรับงานและขอบเขตเดิม

### 3. `fuse_project_new` — ผูก tier หนึ่งชุดกับโฟลเดอร์หนึ่งโฟลเดอร์

สร้าง skeleton ของ HyperFrames (config ของมัน สกิลของมัน CLAUDE.md ของมัน), ที่เก็บคลิป, และ Noto Sans Thai เป็นไฟล์ในโปรเจกต์ จากนั้น tier/resolution/aspect ถูกล็อกกับโปรเจกต์นี้ — `fuse_scenes` จึงไม่รับสามค่านี้อีก

- **มันไม่คืนขนาด canvas** และนั่นถูกต้อง: กล่องพิกเซลจริงของ "480p 16:9" ต่างกันตาม provider (เคยได้ 864×480 กับ 832×480) ตอนสร้างโปรเจกต์ยังไม่มีคลิปให้วัด canvas มาจาก `fuse_manifest` เท่านั้น **ห้ามเดาและห้ามคำนวณจากชื่อความละเอียด**
- เรียกซ้ำกับโฟลเดอร์เดิมได้ มันคืนงานเดิม แต่ถ้าขอ tier/resolution/aspect ไม่ตรงกับที่ผูกไว้ มันจะปฏิเสธพร้อมบอกว่าใช้ไปกี่ token แล้ว นั่นคือการป้องกันการไปหักเงินผิด tier ไม่ใช่บั๊ก ให้ใช้โฟลเดอร์ใหม่
- อ่าน `warnings` ทุกครั้ง ถ้าโหลดฟอนต์ไม่สำเร็จ (ออฟไลน์) โปรเจกต์ยังใช้ได้แต่ข้อความไทยจะติด lint ของ HyperFrames ตอนเรนเดอร์ ให้บอกผู้ใช้ตอนนี้ ไม่ใช่ตอนเรนเดอร์ล้ม

### 4. `fuse_scenes` — ตัวเดียวที่ใช้เงิน

ส่ง `dir`, `maxTokens` และรายการซีน (slug, prompt, seconds, และ `imageUrls`/`lastImageUrl` ถ้า tier รองรับ)

- **`maxTokens` คือเพดานของโปรเจกต์ทั้งก้อน** รวมที่จ่ายไปแล้ว ไม่ใช่เพดานของการเรียกครั้งนี้ ถ้าซีนที่ขอจะทะลุเพดาน **จะไม่มีอะไรถูกส่งและไม่มีอะไรถูกหัก** การเพิ่มเลขนี้คือการอนุญาตให้ใช้เงินเพิ่ม จึงต้องมาจากผู้ใช้
- **มันบล็อกไม่เกิน `waitMs` (ตั้งต้น 45 วินาที เพราะไคลเอนต์ MCP ตัด tool call ที่ 60 วินาที) แล้วคืนสถานะบางส่วน การเรียกซ้ำด้วยอาร์กิวเมนต์ชุดเดิมคือการรอต่อ ไม่ใช่การเริ่มใหม่** ซีนที่จ่ายไปแล้วไม่ถูกส่งซ้ำ เรียกซ้ำจึงฟรี และกู้งานได้หลังไคลเอนต์ปิด เซสชันใหม่ หรือเติมเงินแล้วมาทำต่อ **ห้ามสร้างโปรเจกต์ใหม่หรือเปลี่ยน slug เพราะเห็นว่าค้าง**
- การเปลี่ยน prompt หรือวินาทีของซีนที่จ่ายแล้ว = คลิปใหม่ = จ่ายใหม่ ส่วนการเปลี่ยนชื่อ slug ไม่ทำให้จ่ายซ้ำ ถ้าผู้ใช้อยากแก้ภาพของซีนที่มีคลิปอยู่แล้ว ให้บอกราคาก่อนแก้
- อ่าน `stopped` และ `detail` เสมอ `insufficient_tokens` = บัญชีถูกปฏิเสธ (เติมเงินแล้วเรียกซ้ำ ทำต่อจากซีนที่ค้าง) · `over_budget` = เพดานที่ผู้ใช้ให้ไม่พอ (ขอเพิ่ม) · `rejected_by_api` = **ข้อความใน `detail` คือกฎจริงของเซิร์ฟเวอร์** เช่นช่วง duration ของ tier หรือจำนวนภาพอ้างอิงที่รับได้ ให้อ่านและทำตามนั้น ไม่เดากฎเอาเองและไม่ลองยิงซ้ำเพื่อหาขอบ
- ไฟล์คลิปถูกโหลดลงโปรเจกต์ให้แล้ว เราไม่ส่ง URL ผลลัพธ์ออกมาเพราะลิงก์ของ provider หมดอายุได้ ให้ทำงานกับไฟล์ในโปรเจกต์เท่านั้น

**ภาพอ้างอิงต้องเป็น URL ที่เซิร์ฟเวอร์เปิดได้เอง** ไฟล์ในเครื่องส่งไม่ได้ และคีย์ API อัปโหลดไฟล์ขึ้น Fuse ไม่ได้ในวันนี้ ถ้าผู้ใช้มีแต่ไฟล์ในเครื่อง ให้บอกตามจริงว่าเส้นทาง i2v ยังไม่เปิดสำหรับคีย์ API — ไม่ส่ง prompt เปล่าแทนภาพ ไม่เปลี่ยนไปใช้ภาพสินค้าอื่น และไม่เปลี่ยนสิทธิ์แชร์ไฟล์ของผู้ใช้ให้เป็นสาธารณะเพื่อให้ผ่าน

### 5. ตรวจทุกซีนก่อนทำซีนถัดไป

เมื่อได้ไฟล์ ให้เปิดดูของจริง เทียบกับบอร์ดที่ต้น–กลาง–ท้ายของช็อตและที่รอยต่อ ตรวจสินค้า (รุ่น รูปทรง สี โลโก้ ตัวอักษรบนแพ็ก) ตัวละคร (หน้า ผม เสื้อผ้า) ทิศการเคลื่อนและการกระทำ

ถ้าพบความผิดเพี้ยน อ้างอิงขาด หรือ tool รักษาข้อกำหนดไม่ได้: **หยุดส่งซีนถัดไป** แจ้ง Shot ID ปัญหา ผลกระทบ และวิธีแก้ที่เจาะจง ระหว่างหยุดให้ตรวจและเตรียมวิธีแก้ได้ แต่ถ้าวิธีแก้ต้องเปลี่ยนภาพ คน สินค้า เสียง หรือแผนที่อนุมัติไว้ ต้องให้ผู้ใช้อนุมัติก่อน **ห้ามเงียบแล้วเปลี่ยนสินค้า คน เสียง หรือยิงซ้ำเพื่อเสี่ยงเดา** — การยิงซ้ำด้วย prompt ใหม่คือการจ่ายเงินใหม่

แยกสามสถานะให้ชัดทุกครั้งที่รายงาน: **สร้างสำเร็จ** ≠ **ตรวจแล้ว** ≠ **ผู้ใช้อนุมัติแล้ว** ไม่เรียกคลิปที่เพิ่งดาวน์โหลดว่าผ่าน

ถ้าแผนให้ทำเป็นคู่หรือเป็นชุดซีนที่ติดกัน ให้ตรวจทั้งภายในคู่และข้ามคู่ก่อนทำชุดถัดไป ภาพนิ่งหนึ่งใบและ prompt ไม่รับประกันทุกเฟรม ถ้างานต้องตรงระดับพิกเซล ให้ไปทางคอมโพสิตในขั้น 4 ไม่ใช่ยิงซ้ำเรื่อย ๆ

### 6. `fuse_narration` — พากย์ ถ้าแผนมีพากย์

ข้ามข้อนี้ไปได้ถ้างานไม่มีเสียงพูด **ตัวนี้ใช้เงินของบัญชี ElevenLabs ของผู้ใช้ ไม่ใช่ token ของ Fuse** คนละบัญชี คนละบิล จึงต้องพูดถึงเป็นงบแยกเสมอ และห้ามเอายอดสองก้อนมารวมกันเป็นตัวเลขเดียว

- ใช้ **voice id ที่ผู้ใช้เลือกไว้ในขั้นวางแผน** ห้ามเลือกใหม่หรือเปลี่ยนเสียงเอง ถ้ายังไม่มี ให้กลับไปขั้น 2 ให้ผู้ใช้เลือกจาก `fuse_voices` ก่อน
- ยิง `dryRun: true` ก่อนทุกครั้งที่บทเปลี่ยน แล้วให้ผู้ใช้เห็นยอดตัวอักษรและอนุมัติ จากนั้นจึงยิงจริงด้วย `maxCharacters` เท่ายอดที่อนุมัติ **ถ้าเกินเพดาน จะไม่พากย์อะไรเลยและไม่คิดเงิน** ซึ่งเป็นพฤติกรรมที่ต้องการ ไม่ใช่ความผิดพลาด
- **ยิงซ้ำด้วยบทเดิมไม่เสียเงิน** บรรทัดที่พากย์แล้วถูกใช้ไฟล์เดิม เปลี่ยนชื่อ slug ก็ไม่เสียเงิน · แต่ **แก้คำเดียวคือเสียงใหม่ที่จ่ายใหม่** ฉะนั้นอย่า "ลองสร้างดูก่อนแล้วค่อยเกลาบท"
- ถ้าได้ `stopped: quota_exhausted` คือตัวอักษรในบัญชี ElevenLabs ของผู้ใช้ไม่พอ **ไม่ใช่เรื่องคีย์ Fuse และไม่ใช่เรื่องคีย์ผิด** ให้บอกยอดที่เหลือกับยอดที่ต้องใช้ตามที่ `detail` บอก
- รายงานความยาวของแต่ละไฟล์ (`seconds`) ต่อให้ขั้น 4 เพราะเป็นตัวเลขที่ใช้ตัดภาพให้ตรงเสียง

### 7. `fuse_manifest` — วัดก่อนส่งต่อ

เมื่อทุกซีนผ่านแล้ว เรียก `fuse_manifest` มันอ่านคลิปด้วย ffprobe แล้วเขียน `assets/scenes/manifest.json`: canvas ที่ต้องใช้, **ความยาวจริง**ของแต่ละซีน, **`fps`** ที่คลิปเป็นจริง ๆ และ **`hasAudio`** ว่าคลิปมีเสียงติดมาหรือไม่ ทุกค่าต้องมาจากการวัด (ขอ 5 วินาทีแล้วได้ 5.167 เป็นเรื่องปกติ — composition ที่วางบน 5.000 จะตัดท้ายซีนหาย)

**`hasAudio` ไม่ใช่คำสัญญาของ tier แต่เป็นของที่ provider คืนมาจริง** `fuse_tiers` วันนี้ยังไม่บอกว่า tier ไหนมีเสียง เพราะงั้น manifest คือที่เดียวที่รู้ ถ้าเป็น true ให้บอกผู้ใช้ว่าคลิปมีเสียงมาด้วยและเสียงนั้นรวมอยู่ในราคาที่จ่ายไปแล้ว เขาจะได้เลือกว่าจะเก็บ จะมิกซ์ทับ หรือจะทิ้ง — ไม่ใช่ให้ขั้นตัดต่อ mute ทิ้งเองโดยไม่มีใครรู้

จากนั้นส่งต่อ `04-editing` พร้อม: รายการซีนที่ผ่านกับ Shot ID และช่วงเวลา, เวอร์ชันที่ถูกแทนที่, **ไฟล์พากย์ใน `assets/audio/` พร้อมความยาวที่วัดได้รายบรรทัด**, ไฟล์ดนตรีและ SFX ที่ผู้ใช้ให้มา, บทล่าสุด และคำกำกับรอยต่อ

## คีย์และความลับ

คีย์มาจาก environment ของ MCP server เท่านั้น **อย่าขอให้ผู้ใช้วางคีย์ในแชต อย่าพิมพ์ค่าคีย์ และอย่าค้นหาคีย์ทั่วเครื่อง** ถ้าไม่มีคีย์ `fuse_tiers` กับ `fuse_quote` ยังทำงานได้ (ราคาเป็นข้อมูลสาธารณะ) ส่วนเส้นที่ใช้เงินจะหยุดพร้อมบอกว่าต้องตั้ง `FUSE_API_KEY` ที่ไหน — นั่นคือคำตอบที่ถูกต้องสำหรับคำถาม "เชื่อมแล้วหรือยัง" ไม่ต้องสร้างงานคิดเงินเพื่อพิสูจน์ว่าคีย์ใช้ได้

## สิ่งที่แพ็กเกจนี้ไม่ทำ

- **ไม่สร้างดนตรี Ambience หรือ SFX** มีแต่พากย์ (`fuse_narration`) สามแทร็กที่เหลือมาจากฝั่งผู้ใช้และไปมิกซ์ในขั้น 4 อย่าสลับเส้นทางหรือซื้อแพ็กเกจบริการอื่นแทนผู้ใช้
- **ไม่ปั้นเสียงบนบัญชีของ Fuse** พากย์คิดเงินจากบัญชี ElevenLabs ของผู้ใช้เท่านั้น ถ้าไม่มี `ELEVENLABS_API_KEY` คำตอบคือบอกว่าต้องตั้งค่าอะไร ไม่ใช่หาทางอื่นให้มีเสียง
- **ไม่ห่อคำสั่งของ HyperFrames** การเรนเดอร์และตรวจทำผ่าน shell ในขั้น 4 ตามสกิลของ HyperFrames เอง
