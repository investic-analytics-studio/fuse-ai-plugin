# ขั้น 1 — วิเคราะห์ Asset

งานของขั้นนี้จบที่ **analysis brief** ไม่ใช่คลิป ขั้นนี้ไม่เรียก tool ของ Fuse และไม่ใช้เงิน ถ้าผู้ใช้ขอทั้งวิเคราะห์และแผนในคราวเดียว ให้วิเคราะห์ก่อนแล้วส่ง brief ต่อให้ `02-planning` โดยแยกผลสองส่วนให้เห็นชัด

## ตรวจแหล่งข้อมูลจริงก่อนสรุป

- เปิดไฟล์จริงทุกไฟล์ที่ผู้ใช้ให้มา บอกชนิดและตำแหน่งไฟล์ตามจริง เมื่อสุ่มดูเฟรมให้บอกช่วงที่ตรวจ อย่าอ้างว่าดูครบทุกเฟรม
- แยกให้ชัดสี่อย่าง: **สิ่งที่เห็น** / **ข้อมูลจากแหล่งอื่น** (พร้อมลิงก์) / **การตีความ** / **สิ่งที่ยังยืนยันไม่ได้**
- ภาพจัดเสิร์ฟหรือภาพโฆษณาไม่ยืนยันว่าทุกอย่างในภาพอยู่ในแพ็ก อย่าตั้งชื่อวัตถุดิบที่ภาพยังแยกไม่ออก และอย่าเดาข้อมูลด้านที่ถูกบัง
- ค้นข้อมูลเพิ่มเมื่อชื่อรุ่น ส่วนประกอบ วิธีใช้ หรือคำกล่าวอ้างต้องการการยืนยัน ระบุขอบเขตของรุ่น/ล็อต/ช่วงเวลา

## Extract Elements

เลือกเฉพาะหัวข้อที่มีข้อมูลจริง:

- **สินค้า:** ชื่อ รุ่น รส รูปทรง สี แพ็ก โลโก้ ข้อความบนแพ็กที่ต้องคงตรงต้นฉบับ
- **ภาพ:** มุมกล้อง ระยะภาพ การจัดวาง แสง พื้นผิว พาเลตต์ ฉาก พร็อพ การเคลื่อนไหว จังหวะเปลี่ยนภาพ
- **เสียง:** เสียงพูด ดนตรี เสียงจริง ความสัมพันธ์กับภาพ ระบุถ้ายังไม่ได้ฟัง
- **เรื่องและคน:** ลำดับภาพ บทบาทของคน/มือ ปฏิกิริยาที่เห็นจริง ข้อความบนจอ จุดดึงดูด จุดพิสูจน์ CTA ที่มีอยู่
- **Mood & Tone ของเรฟ:** ความรู้สึกที่ภาพสร้างและวิธีสื่อสาร แยกสิ่งที่สังเกตได้จากทิศทางใหม่ที่เสนอ

สรุปว่าองค์ประกอบใด **ใช้เป็นหลักฐาน** / **ใช้เป็นเรฟภาพ** / **ต้องถ่ายเพิ่ม** / **ยังต้องยืนยัน** ไม่คัดลอกตัวตนคน ฉากหลัง ลายน้ำ หรือข้อความจากเรฟที่ไม่เกี่ยวกับสินค้าที่จะขาย

## สองเรื่องที่ขั้นนี้ต้องตอบ เพราะมันล็อกแผน

**1. ภาพอ้างอิงเข้าถึงได้จากอินเทอร์เน็ตไหม**

tier แบบ image-to-video รับภาพอ้างอิงเป็น **URL ที่เซิร์ฟเวอร์ของ Fuse เปิดได้เอง** เท่านั้น ไฟล์ในเครื่อง (`C:\...`, `./product.jpg`) ส่งไม่ได้ และคีย์ API อัปโหลดไฟล์ขึ้น Fuse ไม่ได้ในวันนี้ ให้ระบุใน brief ว่าภาพสินค้าแต่ละใบอยู่ในสถานะใด:

- มี URL สาธารณะอยู่แล้ว (เช่นบนเว็บสินค้าของผู้ใช้เอง) → ใช้ i2v ได้
- มีแต่ไฟล์ในเครื่อง → **แผนต้องวางบน text-to-video** หรือผู้ใช้ต้องเอาภาพขึ้นที่ของตัวเองก่อน อย่าตั้งสมมติฐานว่าเดี๋ยวอัปโหลดได้ และห้ามเปลี่ยนสิทธิ์แชร์ของไฟล์ผู้ใช้เองเพื่อให้เป็นสาธารณะ

ถ้าความตรงของแพ็กคือหัวใจของงาน (ตัวอักษร โลโก้ สีต้องตรงทุกมุม) แล้วยังไม่มี URL ให้บอกตรง ๆ ว่านี่คือตัวบล็อก ไม่ใช่รายละเอียดปลายทาง

**2. เสียงมาจากไหน**

**ถามผู้ใช้ตรง ๆ ในขั้นนี้ อย่าเดาและอย่าปล่อยไว้ให้ขั้นตัดต่อเจอ** แพ็กเกจนี้แยกเสียงเป็นสองพวกที่มีคำตอบไม่เหมือนกัน:

- **เสียงพูด / พากย์ — สร้างได้ในแพ็กเกจนี้** แต่วิ่งบน **บัญชี ElevenLabs ของผู้ใช้เอง** ต้องมี `ELEVENLABS_API_KEY` ตั้งไว้ใน environment ของ MCP server และผู้ใช้ต้องเป็นคนเลือกเสียงเอง — เสียงคือผู้นำเสนอของโฆษณา ไม่ใช่ค่าตั้งต้นที่เลือกแทนกันได้ · ค่าใช้จ่ายคิดเป็นจำนวนตัวอักษรโดย ElevenLabs **ไม่ใช่ token ของ Fuse** คนละบัญชี คนละบิล คนละที่เติมเงิน · การเลือกเสียงและการล็อกบทเกิดในขั้นวางแผน ขั้นนี้แค่ยืนยันว่ามีคีย์หรือไม่
- **ดนตรี, Ambience, SFX — แพ็กเกจนี้ไม่สร้าง** ต้องมาจากฝั่งผู้ใช้ (อัดเอง ฟุตเทจ หรือคลังที่มีสิทธิ์) ขั้นตัดต่อเป็นคนมิกซ์

ถ้ายังไม่มีคีย์ ElevenLabs ให้บอกตรง ๆ ว่างานจะได้คลิปที่**ไม่มีเสียงพูด** และนั่นเป็นการตั้งค่าครั้งเดียวที่ต้องทำก่อน ไม่ใช่สิ่งที่ขั้นตัดต่อแก้ให้ได้

บาง tier มีเสียงติดมากับคลิปจากโมเดลเอง ซึ่งอาจเป็นคนละคนในแต่ละซีน การมีเสียงติดมาจึงไม่ใช่คำตอบของ "ใครพากย์"

## ผลส่งต่อให้ `02-planning`

brief กระชับที่มี: ตัวตนสินค้าและ Asset (บทบาทของแต่ละไฟล์), ข้อเท็จจริงที่ใช้ขายได้พร้อมหลักฐาน, ข้อจำกัดและข้อมูลที่ยังขาด, ลำดับภาพในคลิปอ้างอิง, Extract Elements, Mood & Tone ที่สังเกตได้, องค์ประกอบที่ต้องคงเดิม (รูปทรงแพ็ก ตัวอักษร การจัดวาง เอกลักษณ์ตัวละคร), สถานะภาพอ้างอิงตามข้อ 1 และแหล่งเสียงตามข้อ 2 (มีคีย์ ElevenLabs หรือไม่ · ถ้าเลือกเสียงแล้วคือ id ใด · ดนตรีกับ SFX มาจากไหน)

ยังไม่กำหนด Hook, Tagline, Concept, Character หรือ Script แทนผู้ใช้ในขั้นวิเคราะห์ล้วน สิ่งที่ผู้ใช้เลือกหรือแก้ไว้แล้วให้บันทึกเป็น **creative decisions ที่ต้องรักษา** และห้ามเขียนทับด้วยการตีความใหม่ เมื่อไม่รู้มุมหรือส่วนประกอบ ให้ระบุว่าต้องหาอะไรและขอภาพเพิ่มอย่างไร ไม่สร้างข้อมูลสินค้าทดแทน
