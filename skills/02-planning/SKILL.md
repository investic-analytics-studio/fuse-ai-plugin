# ขั้น 2 — วางแผนและสตอรี่บอร์ด

ขั้นนี้ยังไม่ใช้เงินและยังไม่เรียก tool ที่สร้างคลิป แต่ **ผลของขั้นนี้คืออินพุตของ `fuse_scenes`** โดยตรง จึงต้องออกมาเป็นรายซีนที่ตั้งชื่อแล้วและมีความยาวต่อซีน

ถ้ามี Asset แต่ยังไม่มี analysis brief ให้ทำ `01-analysis` ก่อน ถ้าผู้ใช้ขอแค่การวิเคราะห์ ให้หยุดที่ขั้นนั้น

## รักษาทิศทางของผู้ใช้

สิ่งที่ผู้ใช้เลือกไว้แล้ว — สินค้า แนวเรื่อง Hook Tagline ความยาว จำนวนซีน ธีมภาพ ตัวละคร รูปแบบเรฟ — คือข้อกำหนดของงาน ไม่ใช่ตัวเลือกที่เปิดใหม่ได้ทุกครั้ง ตัวอย่างที่ผู้ใช้ยกมาเพื่อสอนวิธีคิดไม่ใช่สูตรที่ใช้ซ้ำกับทุกสินค้า ความยาวและจำนวนซีนของงานก่อนไม่ใช่ค่าเริ่มต้นของงานถัดไป

ถ้าผู้ใช้ขอไอเดียแบบเปิด เสนอ 5 แนวที่ต่างกันจริง แต่ละแนวมี Hook และเหตุผลสั้น ๆ ว่าทำไมคนจะหยุดดู ไม่รับประกันว่าจะไวรัล เมื่อเลือกแนวแล้วพัฒนาแนวนั้นต่อโดยตรง

## แกนแผน

- **Goal:** ผลที่อยากให้ผู้ชมคิด รู้สึก หรือทำ รวม CTA เดียวที่อ่านหรือฟังทัน
- **Concept:** แกนความคิดที่ทำให้สินค้ามีเรื่องเล่าและกำหนดภาษาภาพ ไม่ใช่แค่ชื่อรูปแบบคลิป
- **Tagline:** วลีสั้นที่สรุปคำมั่นของแคมเปญ แยกจาก Hook และ CTA
- **Video Type / Ref Type:** หน้าที่หลักของคลิป (demo, explainer, brand story, รีวิวจริง ฯลฯ) แยกจากสิ่งที่หยิบมาศึกษาจากเรฟ (ภาพอาหาร กล้อง VFX การเล่าเรื่อง เสียง) ไม่ต้องใช้ประเภทเดียวกับเรฟทั้งคลิป
- **Mood & Tone / Visual Theme:** สี แสง ฉาก มุมกล้อง เสียง การเปลี่ยนภาพ อย่างเป็นรูปธรรม ต่อยอดจาก Extract Elements
- **Products / Character / Selling Points:** รุ่นหรือรสจริง สิ่งที่อยู่ในแพ็ก ตัวละครและการกระทำที่จำเป็น ผูกทุกจุดขายเข้ากับภาพหรือหลักฐาน ไม่แต่งส่วนผสม ราคา โปรโมชัน รีวิว หรือคุณประโยชน์

## Story, Hook, Script

Story คือการเปลี่ยนแปลงจากจุดเริ่มไปสู่ผลที่สินค้าพิสูจน์ได้ Hook ต้องเป็นประโยค **พร้อมภาพแรกที่เห็นได้จริง** และตั้งคำถามที่คลิปตอบได้

สคริปต์ตามเวลา ให้แต่ละซีนมีหน้าที่หนึ่งอย่าง (เปิดเรื่อง / แสดงสินค้า / พิสูจน์ / เผยผล / พาไป CTA) กำหนดภาพเริ่ม → การกระทำ → ภาพจบ มุมกล้อง เสียงหรือบทพูด ข้อความบนจอ และจังหวะตัด อ่านบทพูดออกเสียงเพื่อดูว่าพอดีเวลา ตรวจว่าความยาวรวมและรายซีนตรงกับที่ผู้ใช้กำหนด ช่วงท้ายต้องตอบคำถามจาก Hook

| เวลา | หน้าที่ซีน / ภาพและการกระทำ | บทพูดหรือเสียงบรรยาย | ข้อความบนจอ | เสียง / จังหวะตัด |
|---|---|---|---|---|

## รูปแบบที่ทำให้แผนนี้ผลิตได้

แผนที่ส่งต่อไป `03-generation` ต้องมีของสี่อย่างนี้ครบ เพราะมันคืออาร์กิวเมนต์ของ tool:

1. **slug ของแต่ละซีน** — ตัวพิมพ์เล็ก ตัวเลข และขีดกลางเท่านั้น (`scene-hook`, `pour-01`) slug คือชื่อไฟล์คลิปและเป็นกุญแจที่ใช้จำว่าซีนไหนจ่ายเงินไปแล้ว ตั้งให้สื่อหน้าที่ของซีน และ **ห้ามเปลี่ยนทีหลังเพื่อความสวยงาม**
2. **ความยาวต่อซีนเป็นวินาที** — ช่วงที่ใช้ได้เป็นกฎของ tier ที่ฝั่งเซิร์ฟเวอร์ ไม่ใช่ค่าที่แพ็กเกจนี้รู้ ให้ดูจาก `fuse_tiers` ก่อนล็อกเวลา และแยก **เวลาที่ซีนนั้นควรอยู่บนไทม์ไลน์** ออกจาก **ความยาวขั้นต่ำที่โมเดลสร้างได้** ถ้าโมเดลสร้างสั้นสุด 5 วินาทีแต่ไทม์ไลน์ต้องการ 3 วินาที นั่นคืองานตัดในขั้น 4 ไม่ใช่เหตุผลให้ขอ 3 วินาทีจากโมเดล
3. **aspect และ resolution เดียวของทั้งงาน** — หนึ่งโปรเจกต์ผูกกับ tier/resolution/aspect ชุดเดียวตั้งแต่สร้าง เปลี่ยนกลางทางไม่ได้ (ต้องขึ้นโปรเจกต์ใหม่) ตัดสินใจเรื่องนี้ในขั้นวางแผน ไม่ใช่ตอนกำลังจะยิง
4. **prompt ต่อซีน** — เขียนจากภาพในบอร์ด ไม่ใช่จากคอนเซปต์ลอย ๆ **การแก้ prompt แม้ตัวอักษรเดียวหลังจ่ายไปแล้วคือคลิปใหม่และเสียเงินใหม่** จึงต้องให้ผู้ใช้อ่าน prompt ก่อน ไม่ใช่หลัง

ถ้า tier ที่เลือกไม่รองรับภาพจบ (`supportsLastImage: false`) ห้ามเขียนในแผนว่าเฟรมจบถูกล็อกแล้ว ให้ระบุว่าควบคุมได้เฉพาะจุดเริ่มและคำกำกับ

## สตอรี่บอร์ด

เมื่อผู้ใช้ขอสตอรี่บอร์ด ให้ส่ง **บอร์ดภาพที่มองเห็นได้** ไม่ใช่ตารางข้อความล้วน เลย์เอาต์ตั้งต้น: พื้นดำ หัวเรื่องใหญ่ กริดสามคอลัมน์ เรียงช็อตซ้าย→ขวา บน→ล่าง แต่ละช่องมี `SHOT N` ภาพช็อตขนาดเด่น และใต้ภาพสามแถวคือ `DESCRIPTION` / `SHOT` / `LOCATION` โดยมีเส้นบางคั่น

- **จำนวนและลำดับช็อตยึดจากสคริปต์ที่ผู้ใช้เลือก** ทำตารางจับคู่ beat → Shot ID ก่อนทำภาพ ไม่เพิ่มช็อตเพื่อเติมกริดและไม่ตัดช็อตเพื่อให้พอดีกริด เจ็ดช็อตก็เจ็ดช่อง
- ภาพในแต่ละช่องต้องเป็นเฟรมที่ตั้งใจใช้จริงในสัดส่วนปลายทาง ไม่ใช้ภาพเรฟที่มีลายน้ำ ภาพ placeholder หรือไดอะแกรม ถ้ายังทำเฟรมจริงไม่ได้ ให้ระบุว่าช็อตนั้นยังไม่เสร็จ และยังไม่เรียกบอร์ดนั้นว่าบอร์ดผลิต
- ถ้าคลิปจริงเป็น 9:16 ต้องวางเฟรม 9:16 จริงในกรอบ ห้ามครอปให้เข้ากับหน้าบอร์ด
- Duration, Script, Sound, transition, สถานะภาพ และใบกำกับการผลิตวางเป็น **ส่วนรายละเอียดใต้บอร์ด** โดยใช้ Shot ID เดียวกัน เพื่อให้หน้าบอร์ดยังอ่านเป็นภาพ

ใบกำกับการผลิตต่อช็อตให้มี: Scene No / Shot ID / หน้าที่ในเรื่อง · timecode และ duration · shot size กับมุมกล้อง · การเคลื่อนกล้อง (พร้อมทิศและความเร็ว) · การเคลื่อนของตัวละครและวัตถุ · บทพูด (แยกจากข้อความบนจอ) · เสียงพร้อมคิวเริ่ม–จบ · ชนิดรอยต่อกับภาพต้นทาง→ปลายทาง · Asset ที่ใช้และสถานะของช็อต

ถ้าทำบอร์ดเป็น HTML และมีลูกศรบอกการเคลื่อน ให้เปิด–ปิดได้และเก็บภาพต้นฉบับไว้ไม่เปลี่ยน ลูกศรดำบนพื้นดำต้องมีขอบขาว มี legend และคำกำกับเป็นข้อความ ไม่ใช้สีอย่างเดียวสื่อความหมาย

## ความตรงกับสินค้า

ใช้แพ็กจริงเมื่อตัวอักษร โลโก้ หรือสีต้องตรงทุกมุม ภาพที่โมเดลสร้างทำรายละเอียดแพ็กผิดได้ และ **ภาพนิ่งหนึ่งใบไม่รับประกันทุกเฟรมของคลิป** ถ้าต้องตรงระดับพิกเซล ให้วางแผนใช้ฟุตเทจจริงหรือคอมโพสิตในขั้นตัดต่อแทนการหวังจาก prompt

เพิ่มเฉพาะท็อปปิง พร็อพ และการกระทำที่มีหลักฐานใน Asset หรือผู้ใช้กำหนด แยกภาพจัดเสิร์ฟออกจากสิ่งที่อยู่ในซองจริง คำกล่าวอ้างเรื่องราคา โปรโมชัน ส่วนผสม หรือความนิยมต้องมีแหล่งพร้อมขอบเขตและช่วงเวลา ถ้าไม่มีข้อกำหนดเรื่องตัวละครและเลือกทาง UGC ให้ใช้คนที่ดูเป็นธรรมชาติ ภาพจากสมาร์ตโฟน แสงสมจริง และไม่คัดลอกตัวตนคนหรือฉากหลังจากเรฟ

## Sound Design

**เสียงพูดในงานนี้มาจาก ElevenLabs เสมอ ไม่ว่าจะเลือก tier ไหน** เสียงที่โมเดลวิดีโอใส่มาเองไม่ได้อ่านบทของใคร เปลี่ยนคนพูดได้ทุกซีน และคุมคำไม่ได้ จึงใช้เป็นเสียงบรรยายไม่ได้ ต้องบอกผู้ใช้ตั้งแต่ตอนเลือก tier ว่า **ค่าพากย์เป็นงบก้อนที่สองบนบัญชีอีกเจ้าเสมอ** (`fuse_narration` บนบัญชี ElevenLabs ของเขา หรือไฟล์เสียงที่เขาทำเอง) · ดนตรี Ambience SFX ก็ยังเป็นไฟล์ของเขาเหมือนเดิม

**แล้วค่อยดู `audio.sound` ของ tier นั้นใน `fuse_tiers`** — ค่านี้ไม่ได้บอกว่าประหยัดค่าพากย์ได้ แต่บอกว่า **จะมีแทร็กที่เราไม่ได้สั่งติดมาด้วยไหม** ซึ่งแปลว่ามีงานเพิ่มในขั้นตัดต่อ ไม่ใช่งานที่หายไป

| `audio.sound` | แปลว่า | ผลต่อแผน |
|---|---|---|
| `always` | Fuse สั่งเปิดเอง โมเดลใส่เสียงมาแน่ | วางแผนไว้เลยว่าต้องเลือกว่าจะเก็บเป็นบรรยากาศหรือตัดทิ้ง และต้องตัดเสียงพูดของโมเดลออกตรงซีนที่มีพากย์ |
| `observed` | Fuse ไม่ได้สั่งอะไร ผู้ให้บริการตัดสินเอง เท่าที่วัดมามีเสียงมาทุกครั้ง | วางแผนเหมือน `always` แต่ห้ามสัญญากับผู้ใช้ เพราะเปลี่ยนได้โดยเราไม่รู้ตัว |
| `unknown` | ไม่ได้สั่งและยังไม่เคยวัดคลิปจริงสักตัว | บอกผู้ใช้ตรง ๆ ว่ายังไม่รู้ และให้ไปรู้ตอนขั้น 4 |

ค่านี้เป็นคำบอกเรื่อง **โมเดลที่อยู่หลัง tier** ไม่ใช่การวัดคลิป ของจริงวัดในขั้น 4 ด้วย `hasAudio` จาก `fuse_manifest` ถ้าสองค่าไม่ตรงกันให้เชื่อการวัด และบอกผู้ใช้ว่าแผนเสียงต้องปรับ — เคยผิดมาแล้วในทางที่บอกว่า "เงียบ" ทั้งที่คลิปจริงมีเสียง

แยกเป็นสี่แทร็ก: Voice Over/บทพูด · BGM · Ambience · SFX ระบุ mood เนื้อเสียง ความเร็ว จุดเข้า–ออก จังหวะเน้น รอยต่อ และการลดดนตรีใต้บทพูดเป็นรายซีน

### Voice Over — ขั้นนี้เลือกเสียงและล็อกบท

พากย์สร้างได้จริงด้วย `fuse_narration` บนบัญชี ElevenLabs ของผู้ใช้ สามอย่างนี้ต้องจบในขั้นวางแผน ก่อนส่งไปขั้นสร้าง:

1. **เรียก `fuse_voices` แล้วให้ผู้ใช้เลือกเสียงเอง** แสดงชื่อกับ id พร้อมตรวจว่าโมเดลที่จะใช้รองรับภาษาของบท (บทไทยต้องเห็น `th` ในรายการภาษา) โมเดลที่พูดภาษานั้นไม่ได้จะออกเสียงผิดและยังคิดเงินเหมือนกัน · **ห้ามเลือกเสียงแทนผู้ใช้** และห้ามเปลี่ยนเสียงกลางคลิป
2. **ล็อกบทพูดเป็นข้อความต่อซีนให้ตรงกับที่จะส่งจริง** รวมเครื่องหมายวรรคตอน เพราะวรรคตอนกำหนดจังหวะการอ่าน และเพราะ **แก้คำเดียวคือเสียงใหม่ที่ต้องจ่ายใหม่** — ถ้าบทยังไม่นิ่ง ยังไม่ต้องสร้างเสียง
3. **เรียก `fuse_narration` ด้วย `dryRun: true`** เพื่อได้จำนวนตัวอักษรที่จะถูกคิดเงิน แล้ว **ให้ผู้ใช้เห็นยอดและอนุมัติ** ยอดนี้ ElevenLabs คิดเป็นตัวอักษร **ไม่ใช่ token ของ Fuse** จึงเป็นงบก้อนที่สองที่ต้องพูดถึงแยกจากงบคลิป

อ่านบทออกเสียงเทียบเวลาซีนก่อนล็อก บทที่ยาวกว่าภาพแก้ด้วยการตัดบท ไม่ใช่เร่งเสียงหรือยืดภาพ

### BGM, Ambience, SFX — ยังเป็นแผน ไม่ใช่ไฟล์

แพ็กเกจนี้ **ไม่สร้าง** สามแทร็กนี้ ทุกไฟล์มาจากฝั่งผู้ใช้ (อัดจริง ฟุตเทจ หรือคลังที่มีสิทธิ์) ให้ระบุที่มาของแต่ละแทร็ก และระบุว่ายัง "เป็นแผน ยังไม่สร้าง ยังไม่ผ่านการฟัง" จนกว่าจะมีไฟล์จริง ดนตรีเปลี่ยนตามช่วงเรื่องได้ แต่การอนุญาตเปลี่ยน BGM ไม่ใช่การอนุญาตเปลี่ยนคนพูด

เสียงที่ติดมากับคลิปจากโมเดลอาจเป็นคนละคนในแต่ละซีนและพูดคนละเรื่องกับบท **งานที่มีพากย์ของตัวเองต้องวางแผนตัดเสียงพูดของโมเดลออกในขั้นตัดต่อเสมอ** ไม่ใช่ปล่อยให้ซ้อนกัน ส่วนเสียงบรรยากาศที่ติดมาจะเก็บไว้ก็ได้ ถ้าฟังแล้วเข้ากับงานและผู้ใช้โอเค

## ส่งต่อขั้นสร้าง

เมื่อผู้ใช้สั่งเริ่มสร้างคลิป หรือถามเรื่องคีย์/ราคา/ความพร้อม ให้ไปที่ `03-generation` พร้อมส่ง: เวอร์ชันบอร์ด, รายการซีน (slug + วินาที + prompt), tier/resolution/aspect ที่เลือก, ภาพอ้างอิงพร้อมสถานะ URL, คำกำกับรอยต่อ, creative decisions ที่ต้องรักษา และ **แผนพากย์: voice id ที่ผู้ใช้เลือก + บทที่ล็อกแล้วต่อซีน + จำนวนตัวอักษรที่อนุมัติ** (หรือระบุว่างานนี้ไม่มีพากย์ และเพราะอะไร)

**การถามว่าพร้อมหรือยังไม่ใช่คำสั่งให้เริ่มงานที่คิดเงิน** และห้ามส่งผลิตก่อนผู้ใช้เห็นราคาจาก `fuse_quote` แล้วอนุมัติ
