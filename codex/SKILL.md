# ทำคลิปด้วย Fuse บน Codex

MCP server ชื่อ `fuse` ให้ tool มา 8 ตัว นี่คือคู่มือว่าใช้มันตามลำดับไหนและห้ามทำอะไร
**อ่านไฟล์อ้างอิงของขั้นนั้นก่อนลงมือขั้นนั้น อย่าทำจากความจำ**

ผู้ใช้ที่เพิ่งติดตั้งเสร็จยังไม่รู้ว่างานนี้มีกี่ขั้นและขั้นไหนหักเงิน และที่นี่ไม่มีคำสั่ง `/fuse:*` คอยบอกเขา
**ถ้าเขาถามว่าเริ่มตรงไหน ถามว่าทำอะไรได้ สั่งทำคลิปแบบยังไม่มีรายละเอียด หรือกลับมาทำงานเดิมต่อ
ให้อ่าน `references/00-start.md` ก่อนตอบ** ในนั้นมีลำดับงานสิบขั้นพร้อมเงื่อนไขว่าต้องได้อะไรก่อนเดินต่อ

## ประตูที่ห้ามข้าม

ที่นี่ไม่มีคำสั่ง `/fuse:*` คอยบังคับลำดับให้ กฎพวกนี้จึงอยู่กับคุณคนเดียว:

- **ไม่สร้างคลิปใด ๆ ก่อนผู้ใช้เห็นยอดจาก `fuse_quote` และอนุมัติเพดาน token เป็นตัวเลข** การถามว่า "เริ่มเลยไหม" ไม่ใช่การอนุมัติให้จ่ายเงิน `fuse_scenes` เป็น tool เดียวที่ใช้เงิน ขั้น 4 เรนเดอร์บนเครื่องเขาและไม่เสียอะไร
- **ไม่เขียน composition ก่อน `fuse_manifest` วัด canvas จากคลิปจริง** ขนาดที่เดาจากชื่อความละเอียดผิดกับบาง provider เสมอ (เคยได้ 864×480 กับ 832×480 จากคำว่า 480p เท่ากัน)
- **"สร้างสำเร็จ" ไม่เท่ากับ "ตรวจแล้ว" และไม่เท่ากับ "ผู้ใช้อนุมัติ"** แยกสามสถานะนี้ทุกครั้งที่รายงาน และ**เกณฑ์ว่าอะไรนับว่าตรวจผ่านอยู่ใน `references/shot-checks.md`** อ่านก่อนตัดสินซีนแรก ไม่ใช่ตอนเจอปัญหาที่ซีนที่ห้า
- **ไม่ใส่ข้อความ ซับ หรือ CTA บนภาพจนผู้ใช้สั่ง** และข้อความทั้งหมดทำในขั้น 4 ไม่ฝากโมเดลวิดีโอเขียนตัวอักษร
- **โปรเจกต์ที่ทำค้าง (มี `.fuse/job.json`) ให้ทำต่อด้วยอาร์กิวเมนต์ชุดเดิม** อย่าเริ่มโปรเจกต์ใหม่ ซีนที่จ่ายไปแล้วจะไม่ถูกนับและจ่ายซ้ำ

## ข้อได้เปรียบของ Codex: เจนภาพเองได้ แล้วส่งต่อให้ Fuse

Codex มี tool `image_gen` ในตัว (สกิลระบบ `imagegen`) จุดนี้ทำให้ขั้น 2 เดินจบได้ในที่เดียว แทนที่จะรอผู้ใช้ส่งรูปมา
ของที่ควรเจนคือ **เฟรมเริ่มของแต่ละซีน ภาพตัวละครหนึ่งใบ ภาพจานหรือแพ็กสำหรับ `i2v` และภาพในสตอรี่บอร์ด**

เส้นทางจากรูปที่เจนไปถึงคลิป มีสี่ต่อ และข้ามไม่ได้:

1. **เจน** ด้วย `image_gen` ตามอัตราส่วนปลายทางจริง (9:16 ก็ต้อง 9:16 ไม่ครอปทีหลัง)
2. **ย้ายเข้าโปรเจกต์** ค่าเริ่มต้นของ `image_gen` คือเซฟไว้ที่ `$CODEX_HOME/generated_images/...` ซึ่งกฎของสกิลนั้นห้ามปล่อยไฟล์ที่งานอ้างถึงไว้ที่นั้น ให้คัดลอกเข้า `<โปรเจกต์>/assets/refs/` ด้วยชื่อที่บอกว่าเป็นซีนไหน เช่น `s02-hook-start.png`
3. **ให้ผู้ใช้อนุมัติรูปก่อนอัป** เพราะขั้นถัดไปทำให้รูปเป็นลิงก์สาธารณะ
4. **`fuse_upload`** ไฟล์ที่อนุมัติแล้ว ได้ URL มา แล้วส่งเป็น `imageUrls` ของซีนนั้น (หรือ `lastImageUrl` ถ้า tier นั้น `supportsLastImage` เป็น true) — `fuse_scenes` อ่านภาพอ้างอิงผ่าน HTTP เอง ไฟล์ในเครื่องส่งตรงไม่ได้ และ `fuse_upload` ไม่เสีย token

ข้อที่พลาดกันบ่อย:

- **`fuse_upload` ทำ URL สาธารณะในคลัง asset ของบัญชีผู้ใช้เอง** ไม่ใช่ที่เก็บชั่วคราวของเรา ถามก่อนอัปทุกครั้ง และอย่าอัปไฟล์ที่เขาไม่ได้ชี้ให้
- **รูปที่ผู้ใช้อนุมัติแล้วคือหลักยึดตัวตน** ห้ามเจนใหม่ให้ "สวยขึ้น" เงียบ ๆ เพราะหน้าตัวละครกับหน้าตาอาหารจะเปลี่ยนทั้งคลิป ถ้าจะแก้ ให้ `image_gen` โหมดแก้ภาพจากไฟล์เดิม แล้วให้อนุมัติใหม่
- **ภาพนิ่งหนึ่งใบไม่รับประกันทุกเฟรม** เฟรมเริ่มคุมได้แค่จุดเริ่ม กลางซีนยังเพี้ยนได้ ตรวจที่ต้น–กลาง–ท้ายของทุกช็อต
- **อย่าเอา `image_gen` ไปทำตัวอักษร โลโก้ หรือกราฟิกข้อความ** โมเดลภาพเขียนตัวหนังสือเพี้ยน ภาษาไทยเพี้ยนกว่าอังกฤษ ของพวกนี้ไปทำในขั้น 4
- **คลิปเป็นตอนหรือหลายซีนที่ตัวละครต้องต่อกัน** ไม่ใช้ `image_gen` เจนหน้าใหม่ทุกซีน ให้ดึงเฟรมท้ายของซีนที่ผ่านแล้วมาเป็นเฟรมเริ่มของซีนถัดไปตาม `references/genre-series.md`

## เสียงพูด

`fuse_narration` เรียก ElevenLabs ด้วยคีย์ของผู้ใช้เอง เป็นเงินกระเป๋าที่สองคนละบริษัทกับ Fuse และคิดตามจำนวนตัวอักษร
**บทภาษาไทยต้องเลือก `modelId` ที่รองรับ `th`** โมเดลตั้งต้นพูดไทยไม่ได้ ถ้าส่งไปจะถูกหยุดด้วย `stopped: model_cannot_speak_script` โดยไม่เสียเงิน
ให้ดูรายชื่อเสียงและโมเดลจาก `fuse_voices` ก่อนวางแผนเสียง และซื้อฟังทีละบรรทัดก่อนล็อกทั้งคลิป รายละเอียดอยู่ใน `references/02-planning.md`
